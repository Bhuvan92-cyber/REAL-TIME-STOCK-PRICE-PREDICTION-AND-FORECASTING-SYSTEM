# Repository cleanup report

## Scope and safety

The cleanup was performed against the existing dirty worktree without reset,
checkout, commit, push, or broad recursive deletion. Existing application
source, models, datasets, migrations, tests, deployment files, and user-created
legacy material were preserved unless an artifact was demonstrably generated.

Baseline inventory recorded before cleanup:

- 209 Git-tracked paths.
- 118 Python source files and 114 Python bytecode files present on disk.
- 70 Markdown/text documentation files.
- 19 pickle and 4 PyTorch model artifacts.
- 6 Supabase migrations.
- 5 notebooks.

Post-cleanup filesystem inventory (excluding `.git` and `frontend/node_modules`):

- 298 files.
- 142,673,920 bytes.
- 50 generated tracked entries removed from the working tree, totaling
  354,349 bytes.
- `logs/` remains empty intentionally because `config.yaml` and the legacy
  dashboard use it as a runtime log location.

## Files deleted

Only generated or disposable artifacts were removed:

- `logs/system.log` — generated runtime log.
- All tracked `__pycache__/*.pyc` entries under `modules/` and `scripts/` —
  interpreter bytecode.
- `real_time_stock_prediction.egg-info/PKG-INFO`,
  `SOURCES.txt`, `dependency_links.txt`, `requires.txt`, and `top_level.txt` —
  editable-install metadata that is regenerated by packaging tools.
- Local `.pytest_cache/`, `frontend/test-results/`,
  `frontend/node_modules/.vite-temp/`, and `frontend/dist/` output — disposable
  local test/build artifacts (not tracked).

No model, CSV dataset, notebook, migration, authentication module, source
module, or dependency lockfile was deleted.

## Files reorganized

No source files were moved. Preserving import paths and deployment references
was safer than relocating the legacy Streamlit tree during a dirty worktree.
The canonical deployment entry points are now called out in `README.md` and
the final deployment runbook.

## Empty directories

No unnecessary empty directory was deleted. `logs/` is intentionally retained
as a runtime path. Git metadata directories and dependency directories were
excluded from cleanup.

## Retained compatibility and review items

The following are intentionally retained and require future, separately
authorized review:

- `app.py`, `dashboard/`, `pages/`, and `deployment/Dockerfile.streamlit`:
  legacy Streamlit compatibility surface still referenced by local workflows.
- `Real-Time-Stock-Market-Analysis-And-Prediction-System/`: duplicated legacy
  data/model/module subtree containing tracked datasets and model artifacts.
  It was not deleted because it contains user/model data and has no complete
  equivalence proof for every artifact.
- `notebooks/`: historical ML methodology and experimentation.
- `models_saved/`, root `AAPL_lstm_scaler.pkl`, `data/`, and legacy processed
  CSVs: model/data artifacts explicitly protected by the cleanup requirements.
- `config.yaml`: loaded by `modules/utils/config_loader.py` and legacy tests.
- `vercel.json`, `VERCEL_DEPLOYMENT.md`, `logo.png`, and `RUN CODE.txt`:
  legacy or unclear deployment/support files; retained rather than deleting
  user-created files without stronger evidence.

## Dependency and documentation decisions

No runtime dependency was removed. The frontend lockfile remains required.
Generated output is now ignored through `.gitignore` entries for Ruff cache,
coverage files, Playwright output, test results, and Vite temporary files.

Documentation was not bulk-deleted because the project contains phase-specific
security, ML, operations, billing, and deployment evidence. The current
deployment authority is
[FINAL_DEPLOYMENT_RUNBOOK.md](FINAL_DEPLOYMENT_RUNBOOK.md); older reports are
retained as historical evidence until a separately approved consolidation.

## Validation

The cleanup itself does not alter runtime code. Previously validated checks
remain applicable, including:

- Backend: 32 deterministic tests passed, 1 live test deselected.
- Frontend: 2 component tests passed.
- Frontend production build passed.
- Playwright: 2 public journeys passed.
- Frontend production and development npm audits: 0 vulnerabilities.
- API `/health`: HTTP 200.
- Migration ordering and workflow YAML parsing passed.
- Docker Compose configuration passed.

Docker image build/runtime and Python 3.12 execution remain CI or account
dependent because the local Docker daemon and Python 3.12 interpreter are
unavailable. Supabase RLS and public cloud deployment remain manual checks.

## Unresolved risks

- The duplicated legacy subtree and Streamlit surface increase maintenance
  cost but remain compatibility-sensitive.
- The local Python 3.10 environment cannot validate the Python 3.12 dependency
  set; CI must run the final `pip check`, `pip-audit`, and test suite.
- No public deployment or live two-user Supabase isolation test was performed.
